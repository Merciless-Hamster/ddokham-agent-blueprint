# 질문 은행

인터뷰에서 실제로 화면에 띄우는 문장을 모아 둔 문서다.
**질문 개수는 고정이 아니다.** 신규 세팅인지 보완인지에 따라 묻는 묶음이 다르고, 0단계에서 이미 알아낸 것은 묻지 않고 초안으로 보여 확인만 받는다.

| 상황 | 묻는 것 |
|------|--------|
| 공통 | 1단계 상황 확인 S1·S2 |
| 신규 세팅 | 결과물 Q1~Q3 · 재료 Q4~Q6 · 과정 Q7 · 에이전트일 때만 구성 Q8~Q9 |
| 보완 모드 | B1·B2 · 조건부 B3 |

필드 이름과 값은 `data-schema.md`의 것을 그대로 쓴다.
질문 문장을 다듬는 것은 되지만 **저장하는 값의 표현은 바꾸지 않는다** (예: `파일로 남는다`를 `파일 저장`으로 바꾸지 않는다).

---

## 진행 규칙

### 묻는 방법

| 규칙 | 내용 |
|------|------|
| 묶어서 묻는다 | AskUserQuestion 도구로 **한 묶음을 한 번에** 띄운다. 한 번에 최대 네 문항, 문항마다 보기 2~4개 |
| 보기에서 고른다 | 모든 질문에 보기를 붙인다. 자유 서술은 Q6·B2 두 개뿐이다 |
| 초안이 먼저 | 빈칸을 묻지 않는다. 0단계에서 찾은 초안이나 AI가 만든 초안을 첫 보기로 두고 고치게 한다 |
| 아는 것은 묻지 않는다 | 사용자가 첫 요청이나 앞 답에서 이미 말한 것, 0단계 초안이 확실한 것은 질문을 띄우지 않고 묶음 요약 문장에 넣어 한 번에 확인받는다 |
| 묶음 요약 | 묶음이 끝날 때마다 **한 줄 요약**으로 확인받고 다음 묶음으로 넘어간다 |
| 되묻기는 한 번 | 답이 안 나오면 되묻기 문장을 한 번만 쓴다. 그래도 안 나오면 `미정`에 넣고 넘어간다 |
| 멈추지 않는다 | **인터뷰가 멈추는 것이 최악이다.** 답이 없으면 비워 두고 진행한다 |
| 직접 묻지 않는 것 | 무엇을 만들지(스킬·도구·에이전트)와 서브 에이전트·스킬을 몇 개 둘지는 **묻지 않는다.** 업무를 묻고 답으로 판정한 뒤 초안으로 보여 준다 |
| 이름 | 만든 사람 이름은 묻지 않고 `만든사람`을 `null`로 둔다. `만든날짜`는 오늘 날짜를 자동으로 넣는다 |

### 시간

| 상황 | 목표 | 한계 |
|------|-----|-----|
| 신규 세팅 | 10분 | 12분 |
| 보완 모드 | 6분 | 8분 |

시작할 때 시각을 기록하고 각 묶음에 들어가기 전에 경과를 확인한다.
**한계를 넘기면 남은 질문을 묻지 않는다.** 남은 항목을 `미정`에 넣고 곧바로 산출물 생성으로 넘어간다.

### 답을 못 받았을 때

`미정` 배열에 **사람이 읽는 항목 이름**으로 적는다.
이 배열은 설계도 화면에 "아직 안 정함"으로 그대로 뜨므로 질문 번호를 적지 않는다.

- 좋음: `["늘 참고하는 자료", "완성 기준"]`
- 나쁨: `["Q5", "결과물.완성기준 필드"]`

### 저장

신규 세팅은 묶음이 끝날 때마다 그때까지 채워진 내용을 `설계도/기획서.md`에 갱신한다. 중간에 끊겨도 이어서 진행하기 위해서다.
보완 모드는 인터뷰 중에 파일을 쓰지 않는다. 보완 항목을 확정한 뒤 보완 문서를 한 번에 만든다.

## 0단계 — 폴더 훑기 (질문 아님)

폴더의 파일을 훑어 **뒤 질문의 초안을 미리 채우고, 신규인지 보완인지 가늠하는** 단계다.
**1분을 넘기지 않는다.**

### 읽는 순서

1. 현재 폴더와 바로 아래 하위 폴더의 목록을 가져온다.
2. 임시 파일(`~$`로 시작), `.git`, `node_modules`, `설계도/` 폴더는 제외한다. `.claude/`는 목록만 본다.
3. 아래 다섯 가지를 찾는다.
4. 결과물 후보를 열어 본다. **큰 파일은 앞부분만 읽는다** — 텍스트는 앞 80줄, 문서·표는 첫 화면 분량이면 충분하다.
5. 읽어서 뽑는 것은 **항목명·구조뿐이다.** 문서 본문과 실제 수치는 어디에도 담지 않는다.

### 찾는 다섯 가지

| 찾는 것 | 단서 | 쓰이는 곳 |
|--------|-----|---------|
| 기존 에이전트 흔적 | 맨 위 `CLAUDE.md`·`AGENTS.md`, `.claude/agents/`, `.claude/skills/`. 이 플러그인 자신의 스킬·커맨드는 세지 않는다 | S1의 기본값 |
| 결과물 후보 (최대 4개) | 완성된 문서 형태 `docx` `xlsx` `pptx` `hwpx` `pdf`가 먼저, `csv` `txt`가 다음 | Q1 보기 |
| 자주 보는 파일 후보 | 파일명의 `양식` `서식` `템플릿` `기준` `규정` `명단` `가이드`, 이런 파일이 모인 폴더 | Q5 초안, 참고 폴더 이름 |
| 프로젝트처럼 보이는 폴더 | 날짜·고객사명·건 이름이 붙은 폴더가 여럿 같은 꼴로 있음 | Q8 초안, 프로젝트 이름 규칙 |
| 보완 기록 | `IMP-`로 시작하는 파일, `CHANGELOG`, `improvements/`, `_ops/` | 보완 모드 5절 |

### 파일에서 뽑아 초안으로 쓰는 것

| 파일에서 보이는 것 | 초안으로 채우는 자리 |
|-----------------|-------------------|
| 문서 제목, 파일 이름 | `결과물.이름`, `이름` |
| 확장자 | `결과물.형식` |
| 표의 머리행, 반복되는 소제목 | Q7 과정 초안, `입력.매번바뀜[].이름` 후보 |
| 파일명의 "월간" "주간" "분기", 날짜 표기 | `결과물.주기` 초안 |
| 같은 이름의 지난 회차 파일이 여러 개 | `결과물.주기`가 반복 업무라는 근거 |
| 여러 폴더에 흩어진 재료 파일 | `입력.매번바뀜[].출처` 후보 |

### 막혔을 때

| 상황 | 처리 |
|------|------|
| 폴더에 쓸 파일이 없다 | `examples.json`의 예시 4종을 Q1의 보기로 띄운다 |
| 파일이 안 열린다 | 파일명과 확장자만으로 추정해 Q1에서 확인받는다 |
| 후보가 5개 이상이다 | 최근에 고쳐진 것 3개만 Q1 보기로 띄운다 |

예시 4종은 이렇게 보인다.

- 정해진 서식에 맞춰 문서 한 건 만들기
- 회의 메모를 회의록으로 정리하기
- 여기저기 흩어진 실적을 모아 월간 보고서 쓰기
- 여러 부서에서 온 엑셀을 한 장으로 모으기

## 1단계 — 상황 확인 (질문 2개)

S1·S2를 **한 번에** 띄운다. 인터뷰를 다 마친 뒤에 묻지 않는다.

### S1. 새로 만들기와 보완

- **화면 문장**: 이번에는 무엇을 하실 건가요?
- **보기**
  - `새로 만들기` — 업무를 맡길 것을 처음부터 설계합니다
  - `기존 에이전트 보완` — 이 폴더의 에이전트를 진단하고 고칠 것을 정리합니다
- **기본값**: 0단계에서 기존 에이전트 흔적이 보였으면 `기존 에이전트 보완`을 첫 보기에 두고 `(폴더에서 찾음)`을 붙인다. 안 보였으면 `새로 만들기`를 첫 보기에 둔다
- **이어지는 곳**: `새로 만들기` → 신규 세팅 질문 / `기존 에이전트 보완` → `improve-mode.md`

### S2. 똑햄 에이전트 규칙

- **화면 문장과 보기**: `ddokham-rules.md` 0절을 그대로 쓴다. 규칙 세 줄을 질문 설명에 붙인다
- **이어지는 곳**: `반영한다` → 진행 / `반영하지 않는다` → `ddokham-rules.md` 0절의 안내 문장으로 끝낸다. 아무 파일도 만들지 않는다

## 신규 세팅 질문

### 결과물 묶음 (Q1~Q3)

Q1·Q2·Q3을 **한 번에** 띄운다. 0단계 초안이 확실한 문항은 빼고 띄운다.

#### Q1. 만들고 싶은 결과물

- **화면 문장**: 어떤 결과물을 만드는 일인가요?
- **보기**: 0단계에서 찾은 후보 이름 3개 + `이 중에 없어요`
  - 파일이 없으면 예시 4종을 보기로 쓴다
  - `이 중에 없어요`를 고르면 이름을 한 줄로 받는다
- **모르겠다고 할 때**: 지난달이나 지난주에 만드셨던 문서 중에 또 만들어야 하는 게 있나요?
- **저장 위치**: `결과물.이름`, `이름`, `결과물.형식`
- **내부 메모**: 이 답이 뒤 질문 전부의 주어가 된다. `이름`은 결과물 이름에 갈래에 맞는 말을 붙여 짓되 갈래 판정이 끝난 뒤에 확정한다

#### Q2. 완성되면 어디로 가나

- **화면 문장**: 이걸 다 만들면 그 다음에는 어디로 가나요?
- **보기** (복수 선택 허용)
  - `파일로 남는다`
  - `누군가에게 보낸다`
  - `여러 사람이 보는 화면에 올린다`
  - `다른 사람이 각자 실행해서 쓴다`
- **모르겠다고 할 때**: 만들고 나서 메일이나 메신저로 누구한테 보내시나요, 아니면 그냥 폴더에 두시나요?
- **저장 위치**: `결과물.전달방식` (배열, 보기 문구를 한 글자도 바꾸지 않는다), `결과물.받는사람`, `결과물.보내는수단`
- **내부 메모**: **갈래 판정의 가장 중요한 축이다.** `다른 사람이 각자 실행해서 쓴다`가 켜지면 도구 갈래가 유력해진다
- **덧붙여 묻기**: `누군가에게 보낸다`를 고르면 받는 사람과 무엇으로 보내는지를 한 마디로 받는다

#### Q3. 만드는 주기

- **화면 문장**: 이건 얼마나 자주 만드시나요?
- **보기**: `매주` / `매월` / `건별로 그때그때` / `분기·연 단위`
- **모르겠다고 할 때**: 작년 한 해로 치면 몇 번쯤 만드셨을까요?
- **저장 위치**: `결과물.주기`
- **건너뛰는 때**: 파일명의 "월간"·"주간"이나 같은 이름의 지난 회차 파일로 주기가 분명하면 묻지 않고 요약 문장에 넣는다

#### 결과물 묶음 요약 문장

> 정리하면 `결과물 이름`을 `주기`마다 만들어서 `전달방식`, 맞을까요?

### 재료 묶음 (Q4~Q6)

Q4·Q5를 **한 번에** 띄우고, Q6은 자유 서술이라 따로 띄운다.

#### Q4. 매번 새로 받는 자료와 그 출처

- **화면 문장**: 만들 때마다 새로 받아야 하는 자료는 무엇인가요?
- **보기** (복수 선택 허용): 0단계에서 찾은 재료 후보 3개 + `이 중에 없어요`
- **이어서 묻기 (출처)**: 그 자료는 어디서 가져오시나요?
  - `내 PC 폴더에 있다`
  - `공유 폴더나 드라이브에서 받는다`
  - `메일이나 메신저로 온다`
  - `사내 시스템이나 웹사이트에서 찾는다`
  - 자료가 여러 개면 각각 출처를 고르게 한다
- **모르겠다고 할 때**: 이 일을 시작할 때 제일 먼저 여는 파일이나 화면이 뭔가요?
- **저장 위치**: `입력.매번바뀜[].이름`, `입력.매번바뀜[].형식`, `입력.매번바뀜[].출처` (모르면 `"미정"` 문자열)
- **내부 메모**: **서로 다른 출처의 개수를 센다.** 이 숫자가 갈래 판정과 자료 모으기를 동시에 돌릴지의 근거다. 출처는 반드시 확보한다

#### Q5. 자주 보는 파일

- **화면 문장**: 만들 때 늘 펴 놓고 보는 파일이 있나요?
- **보기** (복수 선택 허용)
  - `서식이나 양식 파일`
  - `지난번에 만든 같은 문서`
  - `기준표·규정·명단 같은 고정 자료`
  - `없다`
- **모르겠다고 할 때**: 새로 백지에서 쓰시나요, 아니면 지난번 것을 열어서 고쳐 쓰시나요?
- **저장 위치**: `입력.고정참조[].이름`, `입력.고정참조[].형식`
- **내부 메모**: 형식은 가리지 않는다. 에이전트 갈래에서는 이 목록이 참고 폴더에 들어갈 파일이 되고, 스킬 갈래에서는 `쓰는서식스킬`의 근거가 된다
- **파일에서 미리 채우기**: 0단계에서 찾은 자주 보는 파일 후보를 첫 보기로 둔다. 그런 파일이 모인 폴더가 있으면 그 폴더 이름도 함께 보여 준다

#### Q6. 남한테 시키면 꼭 틀리는 것과 되돌아온 이유 (자유 서술)

- **화면 문장**: 이 일을 다른 사람한테 시키면 꼭 틀리는 게 뭔가요? 다 만들고 나서 되돌아오거나 다시 손본 적이 있다면 그 이유도 알려 주세요.
- **보기** (복수 선택 허용, 고르는 용도가 아니라 떠올리게 하는 용도로 띄운다)
  - `숫자나 단위 쓰는 법이 정해져 있다`
  - `쓰면 안 되는 표현이나 꼭 들어가야 하는 문구가 있다`
  - `순서나 분류 기준이 정해져 있다`
  - `다 만들고 나서 되돌아온 적이 있다`
- **이어서 묻기**: 고른 것마다 한 줄씩 적어 달라고 한다. **두세 개까지만 받는다**
- **모르겠다고 할 때**: 후배가 이걸 대신 만들어 오면 어디를 제일 많이 고쳐 주셨나요?
- **저장 위치**: 만들면서 틀리는 것 → `입력.머릿속규칙` (배열)과 `구성.지시요지` / 다 만들고 나서 되돌아온 이유 → `반려사유` (배열)
- **내부 메모**: **이 인터뷰에서 가장 중요한 질문이다.** 여기서 나온 문장이 그대로 지시가 되고, 만든 물건이 쓸모 있는지를 가른다. `머릿속규칙`이 비면 설계도에 경고가 뜨므로 되묻기를 반드시 한 번 쓴다
- **되묻기 문장**: 이걸 다른 사람에게 시켰을 때 꼭 틀리는 게 하나쯤 있으실 텐데요. 표현이든 숫자 처리든 한 줄만 적어 주세요.
- **묻지 않는 방식**: "업무 규칙을 알려 주세요"처럼 추상적으로 묻지 않는다. 틀린 경험을 떠올리게 해야 답이 나온다

#### 재료 묶음 요약 문장

> `자료 개수`개 자료를 `출처 개수`군데서 받아 오고, `자주 보는 파일 이름`을 보면서 만드시는군요.

### 과정 (Q7)

#### Q7. 지금 만드는 순서

- **화면 문장**: 지금은 이런 순서로 만드시는 것 같은데, 맞나요?
- **먼저 할 일**: 질문을 띄우기 전에 **3~6단계 초안을 AI가 먼저 만들어 보여 준다.** 단계마다 `AI` / `사람` / `AI+확인` 중 하나를 붙인다. `반려사유`가 있으면 검토 단계를 초안에 넣는다
- **보기**
  - `맞아요`
  - `순서를 바꿔야 해요`
  - `빠진 단계가 있어요`
  - `필요 없는 단계가 있어요`
- **모르겠다고 할 때**: 이 일을 시작해서 끝낼 때까지, 크게 세 덩어리로 나누면 어떻게 되나요?
- **저장 위치**: `과정[].순서`, `과정[].이름`, `과정[].담당`, `과정[].병렬그룹`, `과정[].루프대상`, `과정[].멈춤조건`
- **내부 메모**: 단계 개수와 성격이 갈래 판정의 축이다. 에이전트 갈래로 정해지면 `담당`이 `사람` 또는 `AI+확인`인 단계를 `구성.사람확인지점`으로도 옮긴다
- **병렬 초안 규칙**: 앞 단계의 결과가 뒤 단계의 입력이면 **같은 `병렬그룹`으로 묶지 않는다.** Q4의 출처가 서로 독립일 때만 자료 수집 단계를 묶는다
- **파일에서 미리 채우기**: 결과물 파일의 소제목 순서, 표의 열 순서가 곧 만드는 순서인 경우가 많다

#### 과정 요약 문장

> `단계 수`단계로 만드시고, 사람이 보는 곳은 `사람확인지점`이군요.

### 갈래 확인 (질문 수에 넣지 않는다)

`track-rules.md`로 판정하고, 6절의 문장 틀로 이유와 함께 보여 준 뒤 뒤집을 기회를 준다.

- 사용자가 그대로 가면 `갈래.선택` = `권장대로`, `갈래.원래권장` = `null`
- 상위 갈래로 올리면 `갈래.선택` = `상위로 변경`, `갈래.원래권장`에 원래 판정을 남긴다
- 스킬이나 도구로 정해지면 구성 묶음을 묻지 않고 산출물 만들기로 넘어간다

### 구성 묶음 (Q8~Q9, 에이전트 갈래만)

`ddokham-rules.md` 4~6절로 구성 초안을 먼저 만든 뒤 Q8·Q9를 **한 번에** 띄운다.

#### Q8. 프로젝트 단위

- **화면 문장**: 이 일은 무엇 하나를 폴더 하나로 묶어 관리하면 좋을까요?
- **보기**
  - 0단계에서 프로젝트처럼 보이는 폴더 패턴을 찾았으면 첫 보기에 `지금처럼 {찾은 패턴}` `(폴더에서 찾음)`
  - `고객사·거래처마다`
  - `한 건마다`
  - `월·주마다`
- **이어서 묻기**: 폴더 이름을 어떻게 지을지 찾은 패턴이나 예(`{날짜}_{이름}`)를 보여 주고 이대로 갈지 묻는다
- **모르겠다고 할 때**: 지난번 것과 이번 것을 따로 찾아봐야 할 때, 무엇으로 구분하세요?
- **저장 위치**: `구성.에이전트.폴더.프로젝트.단위`, `구성.에이전트.폴더.프로젝트.이름규칙`
- **건너뛰는 때**: 찾은 패턴이 하나로 분명하면 묻지 않고 Q9 초안에 넣어 함께 확인받는다

#### Q9. 구성 초안 확인

- **먼저 할 일**: 아래 네 가지를 표로 보여 준다
  - 단계마다 누가 맡는지 (메인 / 서브 에이전트 이름)
  - 서브 에이전트마다 맡는 일과 그렇게 나눈 이유 한 구절
  - 스킬 목록 (범용 / 도메인, 쓰는 곳)
  - 폴더와 파일 이름 — 메인 파일, 참고 폴더와 목차·요약 자리, 프로젝트 폴더 이름 규칙과 현황 파일, 보완 기록 폴더
- **화면 문장**: 이 구성으로 갈까요?
- **보기**
  - `이대로 좋아요`
  - `이름을 바꿀래요`
  - `맡는 곳을 바꿀래요`
  - `빼거나 더할 게 있어요`
- **저장 위치**: `구성.에이전트` 전체, `과정[].맡는곳`
- **내부 메모**: 이름은 0단계에서 찾은 기존 이름이 먼저고, 없을 때 제안한 이름이다. 사용자가 고친 이름은 글자 그대로 저장한다. 서브 에이전트가 넷 이상 나오면 먼저 만들 셋을 고르게 한다

#### 구성 묶음 요약 문장

> 메인 파일 `메인파일`이 길을 안내하고, 서브 에이전트 `개수`개와 스킬 `개수`개가 일을 나눠 맡습니다. 프로젝트는 `단위`마다 `이름규칙` 폴더로 관리합니다.

## 보완 모드 질문

`improve-mode.md` 2절의 진단표를 먼저 보여 준 뒤 B1·B2를 **한 번에** 띄운다. B3는 조건이 맞으면 함께 붙인다.

### B1. 고칠 것

- **화면 문장**: 진단 결과를 보고, 이번에 무엇을 고칠까요?
- **보기** (복수 선택 허용): 진단표에서 `부분`·`없음`이 하나라도 있는 묶음만 띄운다. 최대 넷이다
  - `메인 파일 정리` — 목적과 라우팅만 남기기
  - `서브 에이전트·스킬 나누기` — 직무 정의서와 업무 매뉴얼로 역할 나누기
  - `프로젝트 폴더와 현황 파일` — 프로젝트마다 폴더와 현황 한 장
  - `참고 폴더 위키` — 자주 보는 파일에 목차와 요약 붙이기
  - 모두 `갖춤`이면 이 질문 대신 "무엇이 불편하신가요?"를 직접 입력으로 받는다
- **저장 위치**: 보완 항목 목록
- **내부 메모**: 보기 밖의 요청은 직접 입력(Other)으로 받는다

### B2. 자주 틀리거나 다시 손보는 것 (자유 서술)

- **화면 문장**: 요즘 이 에이전트가 자주 틀리거나, 결과를 다시 손보게 되는 게 있나요?
- **보기** (떠올리게 하는 용도)
  - `서식이나 표기가 자꾸 어긋난다`
  - `엉뚱한 파일을 읽거나 너무 많이 읽는다`
  - `결과물이 여기저기 흩어진다`
  - `특별히 없다`
- **이어서 묻기**: 고른 것마다 최근 사례를 한 줄씩 받는다
- **건너뛰는 때**: 사용자가 첫 요청에서 이미 불편한 점을 말했으면 묻지 않는다
- **저장 위치**: 해당 보완 문서의 `원하는 것`과 `우선순위` 근거

### B3. 건드리면 안 되는 것 (조건부)

**B1에서 두 묶음 이상을 골랐거나, 메인 파일이나 폴더 구조를 바꾸는 묶음을 골랐을 때만 묻는다.**

- **화면 문장**: 지금 잘 되고 있어서 이번에 건드리면 안 되는 게 있나요?
- **보기**
  - `폴더 이름과 위치는 그대로`
  - `지금 쓰는 서식과 결과물 모양은 그대로`
  - `특별히 없다`
- **저장 위치**: 보완 문서 2절 `건드리지 않을 것`
