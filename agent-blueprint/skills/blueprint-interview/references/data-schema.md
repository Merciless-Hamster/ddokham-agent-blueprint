# 설계 데이터 구조

신규 세팅 인터뷰의 결과를 담는 JSON이다. 이 구조가 기획서·설계도·세팅 프롬프트 세 산출물의 공통 원본이다.
설계도 HTML 안 `<script id="설계" type="application/json">` 블록에 그대로 들어간다.

보완 모드는 이 구조를 쓰지 않는다. 보완 모드의 산출물 형식은 `improve-mode.md`에 있다.

키를 한글로 쓰는 이유는 사용자가 열어 볼 수 있어야 하기 때문이다.

## 필드 규칙

### 갈래

| 필드 | 규칙 |
|------|------|
| `판정` | `스킬` · `도구` · `에이전트` 중 하나. 반드시 채운다 |
| `이유` | 한 문장. 판정 근거가 된 답을 그대로 인용한다. 예: "자료가 한 곳이고 중간에 확인할 지점이 없어서" |
| `선택` | 사용자가 권장을 따르면 `권장대로`, 상위 갈래로 올렸으면 `상위로 변경` |
| `원래권장` | `선택`이 `상위로 변경`일 때만 원래 판정을 넣는다. 아니면 `null` |

### 결과물

| 필드 | 규칙 |
|------|------|
| `형식` | 확장자 또는 형태. `docx` `xlsx` `pptx` `pdf` `hwpx` `csv` `웹페이지` `메일` 등 |
| `전달방식` | 배열. `파일로 남는다` · `누군가에게 보낸다` · `여러 사람이 보는 화면에 올린다` · `다른 사람이 각자 실행해서 쓴다` 중 1개 이상. 보기 문구를 한 글자도 바꾸지 않는다 |
| `보내는수단` | `전달방식`에 `누군가에게 보낸다`가 있을 때만 무엇으로 보내는지 한 마디(예: `메일`, `메신저`). 아니면 `null` |
| `완성기준` | 0~4개. 비면 설계도에 "아직 안 정함" |

### 입력

| 필드 | 규칙 |
|------|------|
| `매번바뀜[].출처` | **갈래 판정의 근거.** 서로 다른 출처의 개수를 센다. 모르면 `"미정"` |
| `고정참조` | 자주 보는 파일. 서식·기준표·지난 문서·규정집 등 형식을 가리지 않는다. 에이전트 갈래에서는 참고 폴더에 들어갈 파일 목록이 된다 |
| `머릿속규칙` | **가장 중요한 필드.** 비면 설계도에 경고를 띄운다 |

### 반려사유

다 만든 뒤 되돌아오거나 다시 손본 이유. 갈래 판정에는 쓰지 않는다.
비어 있지 않으면 검토 단계를 `과정`에 두는 근거가 되고, 그 단계가 볼 기준이 된다.

### 과정

| 필드 | 규칙 |
|------|------|
| `순서` | 1부터 연속. 3~8개 |
| `담당` | `AI` · `사람` · `AI+확인` 중 하나 |
| `맡는곳` | 에이전트 갈래에서만 채운다. `메인` 또는 `구성.에이전트.서브에이전트[].이름` 중 하나와 글자까지 같아야 한다. 다른 갈래는 `null` |
| `병렬그룹` | 같은 번호끼리 동시 실행으로 그린다. 순차면 `null` |
| `루프대상` | 이 단계가 끝난 뒤 되돌아갈 단계 번호. 검토 단계에만 넣는다. 아니면 `null` |
| `멈춤조건` | `루프대상`이 있으면 반드시 채운다. 예: `"두 번 고쳐도 남으면 알리고 멈춘다"`. 아니면 `null` |

`담당`이 `사람`이거나 `AI+확인`인 단계의 `맡는곳`은 `메인`이다. 서브 에이전트는 사용자와 직접 주고받지 못한다.

### 구성 — 공통

| 필드 | 규칙 |
|------|------|
| `실행방식` | 갈래가 정한다. 아래 표의 문장을 그대로 쓴다 |
| `지시요지` | 머릿속규칙을 지시 문장으로 옮긴 것 |
| `사람확인지점` | 에이전트 갈래만 채운다. `과정[].담당`이 `사람` 또는 `AI+확인`인 단계를 `"{번호}단계 {이름}"`으로 적는다. 스킬·도구 갈래는 `[]` |

| 갈래 | `실행방식` |
|------|-----------|
| 스킬 | `Claude 계정에 올려두고 말로 시킨다` |
| 도구 | `구성.도구.형태`가 `로컬 웹앱`이면 `주소를 열고 버튼을 눌러 쓴다`, `실행 파일`이면 `실행 파일을 두 번 눌러 쓴다` |
| 에이전트 | `폴더를 Claude Code로 열고 말로 시킨다` |

### 구성 — 갈래별 칸

갈래에 해당하지 않는 칸은 지우지 않고 빈 값으로 둔다.

| 필드 | 스킬 | 도구 | 에이전트 |
|------|------|------|---------|
| `쓰는서식스킬` | 채운다 | `[]` | `[]` |
| `도구` | `null` | 채운다 | `null` |
| `에이전트` | `null` | `null` | 채운다 |

**`쓰는서식스킬`** — 스킬이 결과물을 내보낼 때 빌려 쓸 이미 있는 서식 스킬. `"형식 — 용도"` 꼴의 문자열 배열. 예: `["docx — 회의록 서식 출력"]`. 없으면 `[]`.

**`도구`**

| 필드 | 규칙 |
|------|------|
| `형태` | `로컬 웹앱`이 기본값이다. `실행 파일`은 `track-rules.md` 5절 조건이 맞을 때만 |
| `웹앱으로안되는이유` | `형태`가 `실행 파일`이면 반드시 채운다. 사용자가 한 말을 그대로 한 줄로 옮긴다 |
| `보여주는화면` | `결과물.전달방식`에 `여러 사람이 보는 화면에 올린다`가 있으면 무엇을 보여 주는 화면인지 한 마디. 아니면 `null` |

**`에이전트`** — 채우는 규칙은 `ddokham-rules.md`에 있다.

| 필드 | 규칙 |
|------|------|
| `메인파일` | `CLAUDE.md`가 기본값이다. 폴더에 `AGENTS.md`가 이미 있으면 그 이름을 쓴다 |
| `메인이직접` | 메인이 서브 에이전트에 맡기지 않고 직접 하는 일. 1~4개 |
| `서브에이전트[]` | 1~3개. `이름`은 영문 소문자와 하이픈 또는 한글. `판단기준`은 0~4개. `도구`는 정하지 않았으면 `[]`이고, 채울 때는 `Skill`을 넣는다. `스킬`은 미리 불러올 도메인 스킬 이름 |
| `스킬[]` | `분류`는 `범용` 또는 `도메인`. `쓰는곳`은 서브 에이전트 이름 배열이거나 `["메인"]` 또는 `["모두"]`. `이미있는것`은 빌려 쓸 이미 있는 스킬의 형식 이름(예: `"docx"`)이거나 `null` |
| `폴더.참고` | 자주 보는 파일을 두는 폴더. `이름`·`목차`·`요약` 세 칸 모두 그때그때 정한 이름이다 |
| `폴더.프로젝트` | `단위`는 무엇 하나가 폴더 하나인지(예: 고객사별·건별·월별). `이름규칙`은 사용자 방식대로. `안에두는것`은 비어도 된다 |
| `폴더.보완기록` | 에이전트를 고칠 때 쓰는 폴더 이름 |

**폴더 이름은 고정값이 아니다.** 위 예시의 `참고자료/` `00_목차.md` `_요약/` `00_현황.md` `_ops/`는 제안할 때 쓰는 예일 뿐이다.
폴더에 이미 같은 역할을 하는 폴더가 있으면 그 이름을 쓰고, 없으면 업무에 맞게 제안해 사용자가 고친 이름을 쓴다.
한 번 정한 이름은 기획서·설계도·세팅 프롬프트에서 글자까지 똑같이 쓴다.

### 미정

답을 못 받은 항목을 사람이 읽는 이름으로 기록한다. 설계도 하단에 "아직 안 정함"으로 뜬다.

---

## 담지 않는 것

**문서 본문·실제 수치·개인정보를 넣지 않는다.** 항목명·구조·규칙만 담는다.
설계도는 서로 공유하는 산출물이므로 구조 단계에서 막는다.

| 넣는다 | 넣지 않는다 |
|--------|-----------|
| `"표 3열 — 부서별 집행액"` | `"영업2팀 3,240만원"` |
| `"참석자 명단 항목 있음"` | `"김○○, 이○○"` |
| `"금액은 천 원 단위 반올림"` | 실제 금액 |

### 도구

`구성.도구`를 채우고 `구성.에이전트`는 `null`이다. `과정`은 버튼을 누른 뒤 일어나는 처리 순서를 적는다.

```json
"도구": { "형태": "로컬 웹앱", "웹앱으로안되는이유": null, "보여주는화면": "부서별 제출 현황과 합계" }
```

### 에이전트

위 「전체 형태」가 그대로 에이전트 갈래다.
