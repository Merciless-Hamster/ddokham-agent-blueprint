# 하는 일

사용자의 폴더를 훑어 새로 만들지 기존 에이전트를 보완할지 가늠하고, 똑햄 에이전트 규칙을 반영할지 먼저 확인한 뒤 상황에 맞는 질문만 한다.

- 신규 세팅 — 무엇을 만들지(스킬·도구·에이전트) 판정하고 `설계도/` 폴더에 파일 세 개를 만든다.
- 보완 모드 — 기존 에이전트를 진단하고 보완 기록 폴더에 보완 문서를 만든다.

`blueprint-interview` 스킬을 읽고 그 절차를 그대로 따른다.
질문 문구·보기·판정 규칙·똑햄 규칙·산출물 형식은 전부 그 스킬과 `references/` 안의 파일에 있다.
여기 없는 내용을 지어내지 않는다.

# 시작하는 법

인사와 함께 바로 0단계로 들어간다.
설정을 묻거나 준비 작업을 시키지 않는다.

0단계는 질문이 아니라 훑어보기다.
현재 폴더를 훑어 기존 에이전트 흔적, 결과물 후보, 자주 보는 파일, 프로젝트처럼 보이는 폴더, 보완 기록을 찾는다.

1단계에서 두 가지를 한 번에 묻는다.

- 새로 만들지, 기존 에이전트를 보완할지 — 기존 에이전트 흔적이 보였으면 보완을 기본값으로 둔다.
- 똑햄 에이전트 규칙을 반영할지 — 반영하지 않겠다고 하면 안내하고 끝낸다. 아무 파일도 만들지 않는다.

그다음은 고른 쪽의 절차를 따른다. 질문 개수는 정해져 있지 않다. 0단계에서 알아낸 것은 묻지 않고 초안으로 보여 확인만 받는다.

# 만드는 것

신규 세팅이면 `설계도/` 폴더와 그 안의 파일 세 개뿐이다.

- `설계도/기획서.md`
- `설계도/설계도.html`
- `설계도/세팅_프롬프트.md`

보완 모드면 보완 기록 폴더 안의 아래 것뿐이다.

- 보완 항목마다 보완 문서 하나
- 추적표에 보완 문서마다 `제안` 한 줄
- 보완 기록 폴더가 없을 때만 그 골격 — 보완 절차, 변경 이력, 추적표, 보완 문서 틀 네 파일

폴더와 파일 이름은 고정하지 않는다. 이미 있는 이름을 따르거나 제안해서 사용자가 고친 이름을 쓴다.

# 절대 하지 않는 것

이 커맨드는 설계까지만 한다.
실제 세팅과 수정은 다음 단계에서 세팅 프롬프트나 보완 문서를 받은 세션이 한다.

- `CLAUDE.md`·`AGENTS.md`를 만들거나 고치지 않는다.
- 작업 폴더·프로젝트 폴더·참고 폴더를 만들지 않는다. 설계도에 적히는 폴더 이름도 실제로 만들지 않는다.
- 서브 에이전트나 스킬 정의 파일을 만들거나 고치지 않는다.
- 설정 파일을 만들지 않고, 초기화 커맨드를 실행하지 않는다.
- 설계한 결과물을 실제로 만들지 않는다. 코드나 스크립트를 쓰지 않는다.
- 폴더에 있던 기존 파일을 고치거나 옮기거나 지우지 않는다. 읽기만 한다. 보완 모드에서 기존 추적표에 한 줄을 추가하는 것만 예외다.

# 끝낼 때

신규 세팅이면 세 파일의 전체 경로를 알려 주고, 설계도는 더블클릭하면 브라우저에서 열린다고 안내한다.
고칠 것이 있으면 `기획서.md`를 고친 뒤 `/ddokham-blueprint-redraw`를 쓰라고 알려 준다.

보완 모드면 보완 문서의 전체 경로와, 새 세션에서 보완 문서 맨 끝의 문장을 붙여 넣으면 구현이 시작된다는 것을 알려 준다.
