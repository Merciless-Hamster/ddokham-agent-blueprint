# 에이전트 설계도

내 업무를 AI에게 맡기고 싶은데 무엇부터 만들어야 할지 모를 때, 그리고 이미 만든 에이전트를 정리하고 싶을 때 쓰는 Claude Code 플러그인입니다.

**똑햄 에이전트 규칙**에 맞춰 설계합니다. 새로 만들 때는 내 업무에 맞는 것이 무엇인지 판정하고 **문서 세 개**를 만들어 주고, 기존 에이전트를 고칠 때는 진단한 뒤 **보완 문서**를 만들어 줍니다.

코딩을 모르는 사람을 위해 만들었습니다. 질문은 모두 보기에서 고르는 형태이고, 폴더에서 알 수 있는 것은 묻지 않고 초안으로 보여 줍니다. 답을 모르면 넘어가도 됩니다.

---

## 설치

Claude Code에서 두 줄이면 됩니다.

```
/plugin marketplace add Merciless-Hamster/ddokham-agent-blueprint
/plugin install agent-blueprint@ddokham
```

## 쓰는 법

만들고 싶은 결과물 파일이 들어 있는 폴더, 또는 고치고 싶은 에이전트 폴더를 Claude Code로 열고 이렇게 칩니다.

```
/ddokham-blueprint
```

그게 전부입니다. 폴더를 먼저 훑어보고 두 가지를 묻습니다.

1. 새로 만들까요, 기존 에이전트를 보완할까요? 폴더에 에이전트가 이미 있으면 보완을 먼저 권합니다.
2. 똑햄 에이전트 규칙을 반영할까요? 반영하지 않으면 여기서 마칩니다.

그다음은 상황에 맞는 질문만 이어집니다. 가져온 파일이 없어도 준비된 예시 네 가지 중에서 고르면 됩니다.

| 커맨드 | 하는 일 |
|--------|--------|
| `/ddokham-blueprint` | 새로 만들 때는 판정과 문서 세 개를, 고칠 때는 진단과 보완 문서를 만들어 줍니다 |
| `/ddokham-blueprint-redraw` | 기획서를 고친 뒤 나머지 둘을 다시 만듭니다 |

## 똑햄 에이전트 규칙

일을 수행하는 에이전트를 위한 규칙입니다. 웹이나 앱을 만드는 바이브코딩용 에이전트에는 쓰지 않습니다.

- **프로젝트 하나 = 폴더 하나.** 업무 프로젝트마다 폴더를 따로 두고, 폴더마다 현황 파일 하나로 진행 상황을 봅니다.
- **참고 폴더와 요약.** 자주 보는 파일은 한 폴더에 모으고 파일마다 요약 md를 붙입니다. 목차와 요약을 먼저 보고 필요한 원본만 열어 시간과 토큰을 아낍니다. 파일 형식은 가리지 않습니다.
- **메인 파일은 길 안내만.** `CLAUDE.md`(또는 `AGENTS.md`)에는 에이전트의 목적과, 어떤 일을 누구에게 보낼지만 적습니다.
- **일은 서브 에이전트와 스킬이 나눠서.** 서브 에이전트는 직무 정의서(역할·판단 기준·도구·보고 형식), 스킬은 업무 매뉴얼(절차·체크리스트·템플릿)입니다. 같은 내용을 양쪽에 쓰지 않습니다.
- **고칠 때는 보완 문서로.** 에이전트를 고치는 일은 보완 기록 폴더에서 보완 문서와 변경 이력으로 관리합니다.

폴더와 파일 이름은 고정하지 않습니다. 이미 쓰는 이름이 있으면 따르고, 없으면 업무에 맞게 제안해서 고칠 수 있게 합니다.

## 새로 만들 때 — 무엇이 나오나

폴더에 `설계도/`가 생기고 그 안에 세 개가 들어 있습니다.

| 파일 | 무엇 |
|------|------|
| `기획서.md` | 무엇을 왜 만드는지 적은 문서. 직접 고쳐도 됩니다 |
| `설계도.html` | 한 장짜리 그림. 브라우저로 열고, 인쇄하면 A4 가로 한 장입니다 |
| `세팅_프롬프트.md` | 실제로 만들 때 붙여 넣는 프롬프트 |

설계도는 재료에서 결과물까지의 흐름을 한 장에 담습니다. AI가 하는 단계와 사람이 봐야 하는 단계를 색으로 나누고, 단계마다 누가 맡는지(메인 또는 서브 에이전트) 표시하고, 아래에 서브 에이전트·스킬·폴더 구성을 보여 줍니다.

### 모든 업무에 에이전트가 필요한 건 아닙니다

자료 하나로 문서 하나 만드는 일에 에이전트를 세우면 관리할 것만 늘어납니다.
이 플러그인은 답변을 보고 세 갈래 중 하나를 골라 주고, **왜 그렇게 판단했는지 이유를 함께** 보여 줍니다.

| 갈래 | 언제 | 만드는 것 | 어디서 쓰나 |
|------|------|----------|-----------|
| **스킬** | 자료 한두 개로 매번 같은 서식의 문서를 만들 때 | 스킬 하나 | 계정에 올려 두고 어디서든 |
| **도구** | 판단은 없고 손만 많이 가는 반복 작업일 때 | 버튼 화면이 있는 도구 | 내 PC, 필요하면 동료에게 |
| **에이전트** | 여러 곳에서 모아 판단이 섞인 결과물을 만들 때 | 똑햄 규칙에 맞춘 메인 파일·서브 에이전트·스킬·폴더 | Claude Code |

애매하면 낮은 쪽을 먼저 권합니다. 크게 만들면 고칠 것도 커지기 때문입니다.
판정이 마음에 안 들면 위 갈래로 올릴 수 있고, 그 사실이 기획서에 남습니다.

---

## 기존 에이전트를 고칠 때 — 무엇이 나오나

먼저 지금 에이전트를 똑햄 규칙 항목마다 갖춤·부분·없음으로 진단한 표를 보여 줍니다. 그 표를 보고 무엇을 고칠지 고르면, 고칠 것마다 보완 문서가 하나씩 생깁니다.

| 무엇 | 내용 |
|------|------|
| 보완 문서 | 배경·제안, 타당성 검토, 구현 계획, 상태 이력. 맨 끝에 새 세션에 붙여 넣을 한 문장이 있습니다 |
| 추적표 한 줄 | 보완 문서마다 `제안` 상태로 한 줄 |
| 보완 기록 골격 | 보완 기록 폴더가 없을 때만. 보완 절차, 변경 이력, 추적표, 보완 문서 틀 |

이미 보완 기록을 쓰고 있다면 그 폴더와 번호 매기는 법과 문서 틀을 그대로 따릅니다.

## 이 플러그인이 하지 않는 것

- 실제로 만들거나 고치지 않습니다. 설계까지가 이 플러그인의 몫이고, 만드는 것은 세팅 프롬프트나 보완 문서를 받은 다음 세션이 이어받습니다
- 메인 파일, 서브 에이전트, 스킬, 작업 폴더를 만들거나 고치지 않습니다. 생기는 것은 `설계도/` 안 세 개, 또는 보완 기록 폴더 안의 보완 문서뿐입니다
- 폴더에 있던 파일을 고치거나 옮기거나 지우지 않습니다
- 문서 내용이나 실제 숫자를 설계도에 담지 않습니다. 항목 이름과 구조만 담습니다. 서로 보여 주는 그림이기 때문입니다
- 어디로도 올리지 않습니다. 전부 내 컴퓨터 안의 파일입니다
