# 원칙

**HTML을 새로 쓰지 않는다.**
`assets/blueprint-template.html`을 복사하고, 그 안의 데이터 블록 하나만 교체한다.

매번 새로 쓰면 사람마다 모양이 달라진다.
여러 사람이 각자 설계도를 만들고 서로 돌려 보는 자리에서는 양식이 같아야 비교가 된다.

템플릿 안에 화면 구성과 그리는 방식이 전부 들어 있다.
설치할 것이 없고 인터넷이 없어도 열린다. 이 성질을 깨뜨리지 않는다.

# 절차

1. 데이터가 `skills/blueprint-interview/references/data-schema.md`의 구조를 만족하는지 확인한다.
   - `갈래.판정`이 채워져 있는가.
   - `과정[].순서`가 1부터 연속인가.
   - `루프대상`이 있는 단계에 `멈춤조건`이 있는가.
   - 갈래에 맞는 `구성` 칸이 채워져 있는가. 스킬은 `쓰는서식스킬`, 도구는 `도구`, 에이전트는 `에이전트`. 해당하지 않는 칸은 `[]`나 `null`이다.
   - 에이전트 갈래면 `과정[].맡는곳`이 모두 `메인`이거나 `구성.에이전트.서브에이전트[].이름` 중 하나와 글자까지 같은가.
   - 필드 이름과 값을 한 글자도 바꾸지 않는다. 이름이 다르면 그림이 비어서 나온다.

2. `assets/blueprint-template.html`을 그대로 복사해 `설계도/설계도.html`로 저장한다.

3. 복사본에서 `<script id="설계" type="application/json">` 여는 태그와 그 뒤의 `</script>` 사이의 내용만 완성된 데이터로 교체한다.

4. 그 밖의 줄은 하나도 건드리지 않는다. 화면 구성·색·글꼴·그리는 방식을 고치지 않는다.

5. 저장한 뒤 데이터 블록이 온전한지 확인한다.
   - 따옴표와 쉼표가 맞는지 본다. 여기가 깨지면 그림이 뜨지 않는다.
   - `세팅프롬프트` 값처럼 여러 줄인 문자열은 줄바꿈을 `\n`으로 바꿔 한 줄짜리 문자열로 넣는다.
   - 값 안에 `</script>`라는 글자가 들어가지 않게 한다. 들어가면 블록이 거기서 끊긴다.

# 다시 그릴 때

같은 절차를 그대로 쓴다.
기존 `설계도.html`을 부분 수정하지 않고, 템플릿에서 다시 복사해 데이터 블록을 넣는다.

부분 수정을 반복하면 파일이 조금씩 어긋난다.
다시 그리기는 언제나 블록 교체 한 번이다.

# 담지 않는 것

문서 본문·실제 수치·개인 정보를 넣지 않는다.
설계도는 서로 돌려 보는 산출물이므로 항목 이름과 구조만 담는다.
폴더와 파일 이름은 데이터에 저장된 이름을 그대로 보여 준다. 템플릿이 이름을 정하지 않는다.

예를 들어 "표 3열 — 부서별 집행액"은 넣고, 그 표에 적힌 실제 금액은 넣지 않는다.

# 끝낸 뒤 안내

- 만들어진 파일의 전체 경로를 알려 준다.
- 파일을 더블클릭하면 브라우저에서 열린다고 알려 준다.
- 인터넷이 없어도 열리고, 따로 설치할 것이 없다고 한 줄로 덧붙인다.
- 고칠 것이 있으면 `기획서.md`를 고친 뒤 `/ddokham-blueprint-redraw`로 다시 그리라고 알려 준다.
