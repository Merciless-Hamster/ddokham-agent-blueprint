# 기획서 형식

`설계도/기획서.md`의 형식이다. 사용자가 읽고 직접 고치는 문서다. 신규 세팅에서만 만든다. 보완 모드의 기획서는 보완 문서이고 형식은 `improve-mode.md` 6절에 있다.
데이터(`data-schema.md`)를 사람이 읽는 문장으로 옮긴 것이고, 사용자가 이 파일을 고친 뒤 다시 그리기를 실행하면 설계도와 세팅 프롬프트가 이 파일 기준으로 다시 만들어진다.

---

## 지켜야 할 것

| 규칙 | 내용 |
|------|------|
| 섹션 구조 고정 | 일곱 개 섹션을 이 순서 그대로 쓴다. 갈래가 달라도 섹션을 빼거나 더하지 않는다 |
| 제목 문자열 고정 | 섹션 제목과 표의 항목 이름을 바꾸지 않는다. 다시 그리기가 이 제목으로 값을 찾는다 |
| 쓰는 말 | `메인 파일` `서브 에이전트` `스킬` `참고 폴더` `현황 파일`은 쓴다. 처음 나올 때 `ddokham-rules.md` 8절의 풀이를 한 번 붙인다. 그 밖의 안쪽 용어(스키마·필드·파싱·컨텍스트 등)는 쓰지 않는다 |
| 한 문장 한 줄 | 문장 중간에서 줄을 바꾸지 않는다 |
| 강조 금지 | 별표 강조를 쓰지 않는다 |
| 원문 금지 | 문서 본문·실제 수치·개인정보를 옮기지 않는다. 항목 이름과 규칙만 적는다 |
| 빈 값 표기 | 값이 없으면 칸을 비우지 말고 `아직 안 정함`이라고 적는다 |
| 목록 길이 | 한 목록은 최대 5개. 넘으면 앞 5개만 적고 나머지는 6번 섹션으로 옮긴다 |
| 이름 | 폴더와 파일 이름은 데이터에 저장된 그대로 적는다. 다른 곳과 글자 하나라도 다르게 쓰지 않는다 |

### 갈래가 달라도 같은 것과 다른 것

| 구분 | 내용 |
|------|------|
| 같다 | 섹션 7개, 순서, 제목, 1~4번 표의 항목 이름 |
| 다르다 | 각 칸에 들어가는 값, 5번 구성 섹션의 내용 |

## 전체 골격

```markdown
# {이름}

> {한줄목표}

- 만든 날: {만든날짜}
- 만든 사람: {만든사람}

## 무엇을 만드나
## 결과물
## 무엇으로 만드나
## 어떤 순서로
## 구성
## 다음 단계
## 아직 안 정한 것
```

`만든사람`이 없으면 그 줄을 넣지 않는다.

## 1. 무엇을 만드나

갈래 판정과 그 이유가 첫 화면에 온다. 무엇을 만드는 사람인지가 한 줄로 보여야 한다.

```markdown
## 무엇을 만드나

| 항목 | 내용 |
|------|------|
| 만드는 것 | {갈래.판정} |
| 그렇게 본 이유 | {갈래.이유} |
| 어떻게 시키나 | {구성.실행방식} |
| 적용 규칙 | {아래 표의 문장} |
```

| 칸 | 채우는 법 |
|----|----------|
| 만드는 것 | `스킬` `도구` `에이전트` 중 하나를 그대로 적는다 |
| 그렇게 본 이유 | 한 문장. 판정 근거가 된 답을 그대로 쓴다 |
| 적용 규칙 | 에이전트 갈래는 `똑햄 에이전트 규칙`. 스킬·도구 갈래는 `똑햄 에이전트 규칙 — 폴더와 담당 구조는 에이전트에만 써서 이번에는 붙이지 않음` |

권장과 다른 갈래를 골랐으면 표 아래에 한 줄을 덧붙인다.

```markdown
권장은 {갈래.원래권장}이었고, 선택은 {갈래.판정}이다.
```

---

## 2. 결과물

무엇이 나오고 어디로 가는지, 그리고 다 됐다고 볼 기준이 무엇인지를 적는다.

```markdown
## 결과물

| 항목 | 내용 |
|------|------|
| 이름 | {결과물.이름} |
| 형식 | {결과물.형식} |
| 어디로 가나 | {결과물.전달방식을 쉼표로 이은 것} |
| 받는 사람 | {결과물.받는사람} |
| 보내는 수단 | {결과물.보내는수단} |
| 얼마나 자주 | {결과물.주기} |

다 됐다고 볼 기준
- {결과물.완성기준 각 항목}

지금까지 되돌아온 이유
- {반려사유 각 항목}
```

| 칸 | 채우는 법 |
|----|----------|
| 보내는 수단 | 보내는 일이 없으면 `없음` |
| 다 됐다고 볼 기준 | 비어 있으면 목록 대신 `아직 안 정함` 한 줄을 적는다 |
| 지금까지 되돌아온 이유 | 비어 있으면 `없음` 한 줄을 적는다 |

되돌아온 이유는 4번 표의 검토 단계가 볼 기준이 된다.

---

## 3. 무엇으로 만드나

입력을 세 갈래로 나눠 적는다. 세 갈래를 합치지 않는다. 매번 바뀌는 자료와 늘 같은 자료는 다루는 방식이 다르다.

```markdown
## 무엇으로 만드나

매번 새로 받는 자료

| 이름 | 형식 | 어디서 가져오나 |
|------|------|---------------|
| {입력.매번바뀜[].이름} | {형식} | {출처} |

자주 보는 파일

| 이름 | 형식 |
|------|------|
| {입력.고정참조[].이름} | {형식} |

머릿속에만 있던 규칙
- {입력.머릿속규칙 각 항목}

지시로 적을 것
- {구성.지시요지 각 항목}
```

| 칸 | 채우는 법 |
|----|----------|
| 어디서 가져오나 | 서로 다른 출처가 몇 개인지가 판정 근거다. 모르면 `미정`이라고 적는다 |
| 자주 보는 파일 | 없으면 표 대신 `없음` 한 줄 |
| 머릿속에만 있던 규칙 | 비어 있으면 목록 대신 아래 경고 한 줄을 적고, 7번 섹션에도 올린다 |
| 지시로 적을 것 | 머릿속 규칙을 지시 문장으로 옮긴 것이다. 규칙과 문구가 겹쳐도 그대로 둔다 |

머릿속 규칙이 비었을 때 넣는 줄.

```markdown
- 아직 안 정함 — 이 칸이 비면 남이 만든 것 같은 결과가 나온다. 여기부터 채우는 것을 권한다.
```

## 4. 어떤 순서로

지금 이 일을 하는 순서를 그대로 적고, 각 단계를 누가 하는지와 어디서 맡는지를 붙인다.

```markdown
## 어떤 순서로

| 순서 | 하는 일 | 누가 하나 | 맡는 곳 | 표시 |
|------|--------|----------|--------|------|
| {과정[].순서} | {이름} | {담당} | {맡는곳} | {표시} |

사람이 볼 곳: {구성.사람확인지점을 쉼표로 이은 것}
```

담당은 아래 말로만 적는다.

| 데이터 값 | 문서에 쓰는 말 |
|----------|--------------|
| `AI` | AI |
| `사람` | 사람 |
| `AI+확인` | AI가 하고 사람이 확인 |

맡는 곳은 에이전트 갈래에서만 채운다. `메인`은 `메인 파일`로, 서브 에이전트는 그 이름 그대로 적는다. 스킬·도구 갈래는 `-`를 적는다.

표시 칸에 쓰는 말도 정해 둔다. 여러 개면 쉼표로 잇고, 해당이 없으면 `-`를 적는다.

| 조건 | 표시 |
|------|------|
| 같은 병렬그룹이 둘 이상 | 동시에 진행 |
| 루프대상이 있음 | {번호}번으로 되돌아감 — {멈춤조건} |

사람이 볼 곳이 없으면 `없음`이라고 적는다.

## 5. 구성

갈래마다 채우는 내용이 다르다. 제목은 같다.

### 스킬 갈래

```markdown
## 구성

| 항목 | 내용 |
|------|------|
| 만드는 것 | 스킬 하나 — {이름} |
| 빌려 쓰는 서식 스킬 | {구성.쓰는서식스킬을 쉼표로 이은 것} |
| 두는 곳 | Claude 계정 — 따로 만드는 폴더 없음 |
```

빌려 쓰는 서식 스킬이 없으면 `없음`이라고 적는다.

### 도구 갈래

```markdown
## 구성

| 항목 | 내용 |
|------|------|
| 만드는 것 | {형태 문장} |
| 보여주는 화면 | {구성.도구.보여주는화면} |
| 두는 곳 | 따로 만드는 폴더 없음 |
```

| 칸 | 채우는 법 |
|----|----------|
| 만드는 것 | `로컬 웹앱`이면 `버튼 화면 — 주소를 열고 버튼을 눌러 쓴다`. `실행 파일`이면 `실행 파일 — 버튼 화면으로 안 되는 이유: {웹앱으로안되는이유}` |
| 보여주는 화면 | 없으면 `없음` |

### 에이전트 갈래

메인 파일, 서브 에이전트, 스킬, 폴더와 파일 네 묶음을 이 순서로 적는다. 각 묶음 이름 뒤에 풀이를 한 번 붙인다.

```markdown
## 구성

메인 파일 — 에이전트의 목적과 길 안내를 적는 파일

| 항목 | 내용 |
|------|------|
| 이름 | {구성.에이전트.메인파일} |
| 목적 | {한줄목표} |
| 메인이 직접 하는 일 | {구성.에이전트.메인이직접을 쉼표로 이은 것} |

서브 에이전트 — 일을 따로 맡아 하고 결과만 보고하는 담당

| 이름 | 맡는 일 | 맡는 단계 | 쓰는 스킬 | 보고하는 것 | 따로 둔 이유 |
|------|--------|----------|----------|-----------|------------|
| {이름} | {맡는일} | {이 이름이 맡는곳인 과정 번호} | {스킬} | {보고형식} | {이유} |

담당별 판단 기준
- {이름}: {판단기준을 쉼표로 이은 것}

스킬 — 담당들이 함께 보는 업무 매뉴얼

| 이름 | 종류 | 담는 것 | 쓰는 곳 |
|------|------|--------|--------|
| {이름} | {분류} | {내용} | {쓰는곳} |

폴더와 파일

| 역할 | 이름 | 규칙 |
|------|------|------|
| 메인 파일 | {메인파일} | 폴더 맨 위. 목적과 라우팅만 둔다 |
| 참고 폴더 | {폴더.참고.이름} | 자주 보는 파일 원본을 모은다. 형식은 가리지 않는다 |
| 참고 폴더 목차 | {폴더.참고.이름}{폴더.참고.목차} | 원본마다 한 줄 |
| 파일별 요약 | {폴더.참고.이름}{폴더.참고.요약} | 원본 하나에 요약 하나. 목차 → 요약 → 필요한 원본 순서로 읽는다 |
| 프로젝트 폴더 | {폴더.프로젝트.이름규칙} | {폴더.프로젝트.단위} 하나에 폴더 하나 |
| 현황 파일 | {프로젝트 폴더}/{폴더.프로젝트.현황파일} | 프로젝트마다 하나. 새로 만들지 않고 고친다 |
| 보완 기록 폴더 | {폴더.보완기록.이름} | 에이전트를 고칠 때 보완 문서와 변경 이력을 둔다 |
```

| 칸 | 채우는 법 |
|----|----------|
| 맡는 단계 | 4번 표에서 맡는 곳이 그 서브 에이전트인 단계 번호를 쉼표로 잇는다 |
| 담당별 판단 기준 | 판단 기준이 없는 서브 에이전트는 줄을 넣지 않는다. 모두 없으면 이 목록을 통째로 뺀다 |
| 스킬의 담는 것 | `이미있는것`이 있으면 끝에 `(이미 있는 {형식} 스킬을 빌려 씀)`을 붙인다 |
| 스킬의 쓰는 곳 | `모두`는 `모든 담당`으로, `메인`은 `메인 파일`로 적는다 |
| 프로젝트 폴더의 규칙 | `안에두는것`이 있으면 `안에 {안에두는것을 쉼표로 이은 것}`을 덧붙인다 |

## 6. 다음 단계

나중에 붙일 것을 적는다. 마지막 줄에 지금 할 일을 붙인다.

```markdown
## 다음 단계

- {다음단계 각 항목}

지금 할 일: 설계도/세팅_프롬프트.md를 새 세션에 붙여 넣는다.
```

에이전트 갈래는 지금 할 일 아래에 한 줄을 더 붙인다.

```markdown
써 보다가 고칠 것이 생기면 /ddokham-blueprint 를 다시 실행해 보완 모드로 정리한다.
```

적을 것이 없으면 목록 대신 `당장은 없음` 한 줄을 적는다.

---

## 7. 아직 안 정한 것

빈 채로 넘어간 것을 숨기지 않는다. 이 목록이 다음 대화의 시작점이 된다.

```markdown
## 아직 안 정한 것

- {미정 각 항목}
```

여기에 반드시 올리는 것.

| 조건 | 올리는 문구 |
|------|-----------|
| 머릿속 규칙이 비었음 | 남이 하면 틀리는 것이 무엇인지 |
| 다 됐다고 볼 기준이 비었음 | 어디까지 되면 다 된 것인지 |
| 자료 출처를 모름 | 어느 자료를 어디서 가져오는지 |

비어 있으면 `없음` 한 줄을 적는다.

## 마지막 줄

문서 맨 끝에 이 한 줄을 넣는다. 문구를 바꾸지 않는다.

```markdown
> 이 문서를 고친 뒤 /ddokham-blueprint-redraw 를 실행하면 설계도와 세팅 프롬프트가 다시 만들어집니다.
```

## 데이터가 들어가는 자리

모든 항목이 어느 섹션에 한 번씩 들어간다. 빠진 항목이 있으면 기획서가 덜 만들어진 것이다.

| 데이터 | 들어가는 곳 |
|--------|-----------|
| `이름` `한줄목표` `만든날짜` `만든사람` | 문서 머리 |
| `갈래.판정` `갈래.이유` `갈래.선택` `갈래.원래권장` | 1 무엇을 만드나 |
| `구성.실행방식` | 1 무엇을 만드나 |
| `결과물` 전체 | 2 결과물 |
| `반려사유` | 2 결과물 |
| `입력.매번바뀜` `입력.고정참조` `입력.머릿속규칙` | 3 무엇으로 만드나 |
| `구성.지시요지` | 3 무엇으로 만드나 |
| `과정` 전체 | 4 어떤 순서로 |
| `구성.사람확인지점` | 4 어떤 순서로 |
| `구성.쓰는서식스킬` `구성.도구` `구성.에이전트` | 5 구성 |
| `다음단계` | 6 다음 단계 |
| `미정` | 7 아직 안 정한 것 |

`세팅프롬프트`는 기획서에 넣지 않는다. 같은 내용이 두 파일에 있으면 어느 쪽이 원본인지 알 수 없게 된다.

## 완성 예시

세 갈래가 같은 틀에 다르게 채워진다는 것을 보이려는 예시다. 분량을 줄여 적었다.

```markdown
# 부서 엑셀 종합 도구

> 여러 부서에서 받은 엑셀을 한 장으로 합쳐 준다

## 무엇을 만드나

| 항목 | 내용 |
|------|------|
| 만드는 것 | 도구 |

| 항목 | 내용 |
```

### 에이전트 갈래

```markdown
# 월간 실적보고 에이전트

> 흩어진 실적 자료를 모아 보고서를 쓰고 보내는 데까지 한다

## 무엇을 만드나

| 항목 | 내용 |
|------|------|
| 만드는 것 | 에이전트 |
| 그렇게 본 이유 | 자료를 세 곳에서 모으고 사람이 검토한 뒤 보내는 데까지 이어져서 |
| 어떻게 시키나 | 폴더를 Claude Code로 열고 말로 시킨다 |
| 적용 규칙 | 똑햄 에이전트 규칙 |

## 어떤 순서로

| 순서 | 하는 일 | 누가 하나 | 맡는 곳 | 표시 |
|------|--------|----------|--------|------|
| 1 | 실적 자료 모으기 | AI | 자료-수집 | 동시에 진행 |
| 2 | 지출 내역 모으기 | AI | 자료-수집 | 동시에 진행 |
| 3 | 숫자 정리와 검산 | AI가 하고 사람이 확인 | 메인 파일 | - |
| 4 | 본문 초안 작성 | AI | 보고서-작성 | - |
| 5 | 검토와 고쳐 쓰기 | AI | 메인 파일 | 4번으로 되돌아감 — 두 번 고쳐도 남으면 알리고 멈춘다 |
| 6 | 내용 확인 후 보내기 | 사람 | 메인 파일 | - |

사람이 볼 곳: 3단계 숫자 정리와 검산, 6단계 내용 확인 후 보내기

## 구성

메인 파일 — 에이전트의 목적과 길 안내를 적는 파일

| 항목 | 내용 |
|------|------|
| 이름 | CLAUDE.md |
| 목적 | 흩어진 실적 자료를 모아 보고서를 쓰고 보내는 데까지 한다 |
| 메인이 직접 하는 일 | 숫자 검산 결과를 보여 주고 확인받기, 초안 검토, 보내기 전 확인 |

서브 에이전트 — 일을 따로 맡아 하고 결과만 보고하는 담당

| 이름 | 맡는 일 | 맡는 단계 | 쓰는 스킬 | 보고하는 것 | 따로 둔 이유 |
|------|--------|----------|----------|-----------|------------|
| 자료-수집 | 출처별 자료를 모아 표로 정리한다 | 1, 2 | 없음 | 모은 파일 경로와 빠진 자료 목록 | 원본 자료를 여러 개 읽어야 해서 |
| 보고서-작성 | 정리된 숫자로 본문 초안을 쓴다 | 4 | 실적보고-서식 | 초안 경로와 숫자별 근거 표 | 출력이 길어서 |

담당별 판단 기준
- 보고서-작성: 표에 없는 숫자는 본문에 쓰지 않는다, '미달'이라는 표현은 쓰지 않는다

스킬 — 담당들이 함께 보는 업무 매뉴얼

| 이름 | 종류 | 담는 것 | 쓰는 곳 |
|------|------|--------|--------|
| 실적보고-서식 | 도메인 | 보고서 서식·문단 구성·숫자 표기 체크리스트 (이미 있는 docx 스킬을 빌려 씀) | 보고서-작성 |
| 참고자료-위키 | 범용 | 참고 폴더 파일이 늘거나 바뀌면 요약과 목차를 고친다 | 모든 담당 |
| 프로젝트-현황 | 범용 | 현황 파일을 만들고 바뀐 칸만 고친다 | 모든 담당 |

폴더와 파일

| 역할 | 이름 | 규칙 |
|------|------|------|
| 메인 파일 | CLAUDE.md | 폴더 맨 위. 목적과 라우팅만 둔다 |
| 참고 폴더 | 참고자료/ | 자주 보는 파일 원본을 모은다. 형식은 가리지 않는다 |
| 참고 폴더 목차 | 참고자료/00_목차.md | 원본마다 한 줄 |
| 파일별 요약 | 참고자료/_요약/ | 원본 하나에 요약 하나. 목차 → 요약 → 필요한 원본 순서로 읽는다 |
| 프로젝트 폴더 | {YYYY-MM}_실적보고 | 월 하나에 폴더 하나. 안에 받은자료/, 결과물/ |
| 현황 파일 | {프로젝트 폴더}/00_현황.md | 프로젝트마다 하나. 새로 만들지 않고 고친다 |
| 보완 기록 폴더 | _ops/ | 에이전트를 고칠 때 보완 문서와 변경 이력을 둔다 |
```
